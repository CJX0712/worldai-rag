# ADR-0004: 评测永远在全新内存索引上进行

状态：已接受 · 作者：晨星

## 背景

最危险的一类缺陷是「指标全错但程序不报错」：若评测复用生产索引，
生产数据的干扰会让黄金语料检索不到，recall 悄悄归零且零异常。

## 决策

1. `evals.evaluate()` 每次新建 MemoryStore + BM25Index，重灌内置黄金集，
   不读不写任何生产索引。
2. 锁死断言：往另一管道灌入干扰文档后，连续两次评测结果必须逐位相等
   （test_eval_fresh_index_deterministic、test_eval_endpoint_deterministic）。
3. E2E 中也包含「摄入干扰后 /eval 指标不变」的断言。

## 后果

- 好：/eval 结果在任何运行状态下确定、可复现。
- 坏：黄金集变更即指标变更，属预期行为（黄金集随仓库版本化）。

# ADR-0001: 每个外部依赖都采用「生产实现 + 零依赖兜底」双实现

状态：已接受 · 作者：晨星

## 背景

系统依赖模型文件（GB 级）、第三方推理库与网络资源。若这些缺失时系统
无法运行，则「干净环境一键复现」与 CI 验证都不成立。

## 决策

每个外部能力（embed / vectorstore / rerank / llm）都定义 Protocol 接口，
提供两个实现：

- 生产实现：ONNX / faiss / GGUF，质量优先；
- 兜底实现：纯 Python 零依赖，正确性优先（哈希嵌入、内存余弦、
  直通重排、抽取式模板生成）。

装配层按环境变量选择，失败时回退兜底并**显式返回错误**。

## 后果

- 好：`python verify.py` 在无网、无模型、无 Key 下全绿；CI 不需要任何模型。
- 好：模块可注入 fake 独立单测。
- 坏：需要维护两套实现；用统一的不变量测试（SPEC 第 3 节）约束行为一致。
- 纪律：回退绝不允许静默——`/health.fallback_errors` 必须可见原因。
